# Поиск наставников

`GET /api/mentors` требует Bearer JWT. Доступен всем авторизованным ролям: Student, Mentor, Tutor.

Пример: `/api/mentors?MinYearsExperience=3&DurationMonths=1&DurationMonths=3&DaysOfWeek=Monday&HasAvailablePlaces=true&MinHoursPerWeek=1.5&MaxHoursPerWeek=5&MinRating=4.5&Sort=Compatibility&Page=1&PageSize=20`.

Все фильтры необязательны и объединяются через AND:

| Параметр | Правило |
| --- | --- |
| `SkillIds` | Повторяемый UUID из каталога `skills`; наставник должен иметь **все** выбранные навыки. До 50 значений. Повторы не влияют на результат. |
| `MinYearsExperience`, `MaxYearsExperience` | Включительные границы опыта в годах, 0–100. Отсутствие обеих границ означает «любой». |
| `DurationMonths` | Повторяемое число месяцев, 1–120. Хотя бы одно должно попадать в диапазон анкеты наставника. |
| `DaysOfWeek` | Повторяемое имя дня (`Monday`…`Sunday`) или значение .NET DayOfWeek (Sunday = 0). Достаточно одного доступного окна в выбранные дни. |
| `HasAvailablePlaces` | `true`: есть свободные места; `false`: мест нет; пропущен: все. Учитываются только пары со статусом Active. |
| `MinHoursPerWeek`, `MaxHoursPerWeek` | Включительный диапазон 0–168, поддерживает дробные значения с точкой. |
| `PlaceOfWork` | Подстрока без учёта регистра, до 255 символов; пробелы по краям убираются. `%`, `_` и `\` трактуются буквально. |
| `MinRating` | Минимальный рейтинг 0–5. Анкеты без рейтинга исключаются только при заданном фильтре. |
| `Sort` | `Compatibility` (по умолчанию), `Rating`, `Experience` — по убыванию; `HoursPerWeek` — по возрастанию. |
| `Page` | Номер страницы от 1. Смещение `(Page - 1) * PageSize` не должно превышать Int32.MaxValue. |
| `PageSize` | Количество наставников на странице, от 1 до 100. По умолчанию 10. |

Неверные значения и перевёрнутые диапазоны возвращают 400. Пустая выборка и страница за концом списка возвращают 200 с пустым `items` и правильным общим количеством.

Ответ содержит `items`, `totalCount`, `page`, `pageSize`, `totalPages`. Карточка: `userId`, `questionnaireId`, `firstName`, `lastName`, `position`, `placeOfWork`, `yearsExperience`, `skills` (`id`, `name`), `rating`, `hoursPerWeek`, `availablePlaces`, `compatibility`.

## Совместимость

Поскольку макет не задаёт формулу, введено явное правило в `MentorCompatibilityService`: навыки — 40 баллов пропорционально совпадениям, дни — 20 пропорционально совпадениям уникальных дней, пересечение длительности — 20, достаточное число часов — 10, совместимый формат общения — 10. Hybrid совместим с обоими форматами. Если в анкете нет навыков или дней, их вес исключается из знаменателя. Итог округляется до целого процента по правилу `floor(score + 0.5)`: например, 62,5 → 63, одинаково в .NET и PostgreSQL. Это совпадение дней, а не проверка пересечения конкретных часов; города, уровни навыков и цели пока не учитываются.

Без анкеты пользователя `compatibility = null`; поиск остаётся доступен, в том числе роли Tutor. При одинаковом значении сортировки используется ID анкеты для стабильной пагинации. Неизвестный рейтинг располагается после известных.

## Хранение и выполнение

Миграция `20261114000100` добавляет nullable `teacher_info.rating`, индексы поиска и переводит недельные часы в numeric. Рейтинг отсутствует у существующих наставников и не редактируется через анкету: заполнение этого поля относится к будущей функции оценок. Поиск не подставляет фиктивные оценки.

Контроллер делегирует сервису. `MentorSearchRequestValidator` находится в `Tutor.Api/Validators` (пространство имён `Tutor.Validators`) и регистрируется автоматически через `AddValidation<IValidationMarker>()`. FluentValidation проверяет фильтры, диапазоны и пагинацию при обработке HTTP-запроса до вызова действия контроллера; невалидный запрос получает 400 и не попадает в сервис. Сервис получает проверенные данные и выбирает выражение совместимости, без повторной валидации. Репозиторий выполняет фильтры, расчёт, сортировку и LIMIT/OFFSET в PostgreSQL. Фильтр навыков использует один массив уникальных ID и сравнивает количество совпадений с количеством выбранных навыков. AutoMapper `ProjectTo` выбирает только поля карточек и навыки текущей страницы, без N+1 и загрузки всех анкет. COUNT и страница читаются в RepeatableRead; если смещение не меньше общего количества, запрос карточек пропускается. Предпочтения текущего пользователя запрашиваются отдельно. Поиск места работы через ILIKE с ведущим `%` может требовать сканирования: при росте каталога стоит измерить план и рассмотреть pg_trgm.

## Проверки

`dotnet test Tutor/Tutor.sln` запускает проверки валидации, формулы совместимости, HTTP-авторизации всех ролей и перевода запросов в PostgreSQL. Интеграционные проверки реальной БД требуют `TUTOR_TEST_POSTGRES` с правами создания тестовой базы. Тесты создают отдельную случайную базу, применяют миграции и удаляют её после выполнения.
